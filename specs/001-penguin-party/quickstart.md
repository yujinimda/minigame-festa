# Quickstart: 펭귄 빙판 걷기 검증 가이드

## 사전 조건

- Node.js 24+, npm
- 폰 실기기 테스트 시: 폰과 개발 머신이 같은 네트워크 (또는 Vercel 프리뷰 URL 사용)

## 실행

```bash
npm ci
npm run dev        # http://localhost:3000
```

## 검증 시나리오

### 1. 참가 동선 (US1)

1. 데스크톱 브라우저에서 `/host` 열기 → QR + 방 코드 표시 확인
2. 폰(또는 모바일 뷰포트 탭)에서 QR 스캔 → `/play?room={roomId}` → 닉네임 입력
3. 3초 내 호스트 로비에 닉네임 표시(AS2), 같은 닉네임 재입장 시 " (2)" 접미사
4. 16번째 입장 시도 → "정원 초과" 거부(AS3)

### 2. 레이스 (US2)

1. 2명 이상 입장 후 호스트 "시작" → 폰 컨트롤러 전환 + 3초 카운트다운
2. 좌/우 교대 탭 → 호스트 화면 펭귄 전진(0.5초 내 반영, SC-002)
3. 같은 쪽 연타 → 기울기 급증 → 넘어짐 + 미끄러지는 연출 + 기록 확정
4. 입력 중단 → 기울기 서서히 드리프트
5. 30초 경과 → 결과 화면 전환

### 3. 순위·다시 하기 (US3)

1. 호스트에 거리 내림차순 순위, 폰에 개인 기록·등수
2. "다시 하기" → 같은 멤버로 로비 복귀 → 재시작 가능

### 4. 엣지

- 레이스 중 폰 새로고침 → 같은 닉네임으로 자동 재접속(승계)
- 레이스 중 새 QR 입장 → "게임 진행 중" 차단
- 호스트 탭 닫기 → 폰에 "방이 종료됨"

## 테스트

```bash
npm run test       # Vitest — 게임 로직·프로토콜(raceId/seq 폐기 규칙)·로스터 규칙
npm run e2e        # Playwright — 호스트+플레이어 2명 스모크 (dev 서버 자동 기동)
npm run lint && npm run build   # build는 정적 export(out/) 생성까지 확인
```

기대: 전부 통과. 판정 로직 상세는 [data-model.md](./data-model.md), 메시지 계약은
[contracts/p2p-protocol.md](./contracts/p2p-protocol.md) 참조.

## 실기기 체크리스트 (자동화 불가 항목 — 배포 전 수동 확인)

iOS Safari(iPhone 13 기준)와 Android Chrome 각 1대 이상:

- [ ] 입장 제스처 후 오디오 언락 성공(효과음 들림), 실패 시 음소거 아이콘 표시
- [ ] 탭·레이스 시작·넘어짐 효과음 재생 / Android는 진동, iOS는 시각 플래시 폴백
- [ ] 화면 잠금 → 해제 후 자동 재접속(닉네임·기록 승계)
- [ ] 백그라운드 전환 → 복귀 시 레이스 상태 복원(스냅샷)
- [ ] 모바일 데이터(비 Wi-Fi)로 연결 성공 여부 — 실패 시 "같은 Wi-Fi" 안내 노출 확인

## 플레이테스트 게이트 (SC 검증 — 배포(11번) 전 go/no-go)

측정 절차와 합격 기준:

| 항목 | 절차 | 합격 기준 |
|---|---|---|
| SC-001 참가 30초 | 이 게임을 처음 보는 사람 3명 이상에게 QR만 보여주고 스톱워치 측정 | 전원 30초 내 로비 입장 |
| SC-002 반영 0.5초 | 15인 접속 상태에서 스냅샷 타임스탬프 기반 입력→호스트 반영 지연 로그 수집 | p95 ≤ 500ms |
| SC-003 10초 이해 | 첫 라운드에서 설명 없이 시작 | 전원이 1회 이상 전진 성공 |
| SC-005 1분 회전 | 시작 버튼→결과 표시까지 시간 측정 | ≤ 60초 |
| 15인 연결 go/no-go | Wi-Fi/모바일데이터 혼합으로 15대(부족하면 기기당 다중 탭 보충) 접속, 3라운드 연속 | 연결 유지·레이스 정상 종료. 실패 시 research R1의 결정지(정원 축소/같은 Wi-Fi 명시/셀프호스트 PeerServer) 중 택일 후 스펙 갱신 |
