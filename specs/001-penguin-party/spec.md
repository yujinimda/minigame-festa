# Feature Specification: 미니게임 페스타 — 펭귄 빙판 걷기

**Feature Branch**: `001-penguin-party`

**Created**: 2026-08-21

**Status**: Draft

**Input**: 설계 문서 `specs/001-penguin-party/design.md` (브레인스토밍 산출물)

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 방 만들기와 참가 (Priority: P1)

호스트가 큰 화면 브라우저에서 방을 열면 QR 코드가 표시된다. 참가자는 폰 카메라로 QR을
찍어 참가 페이지로 이동하고, 닉네임을 입력하면 로비에 입장한다. 호스트 화면 로비에
참가자 목록이 실시간으로 나타난다.

**Why this priority**: 참가 동선이 안 되면 게임 자체가 성립하지 않는다. 파티 현장에서
"QR 찍고 바로 들어와지는" 경험이 이 제품의 첫인상이자 핵심 가치.

**Independent Test**: 호스트 페이지를 열고 폰 2대로 QR을 찍어 닉네임 입력 → 호스트
로비에 두 명이 표시되면 통과. 게임 없이도 단독 검증 가능.

**Acceptance Scenarios**:

1. **Given** 호스트가 방을 연 상태, **When** 참가자가 QR을 스캔, **Then** 참가 페이지가 열리고 닉네임 입력 화면이 표시된다
2. **Given** 참가자가 닉네임을 입력, **When** 입장 확정, **Then** 3초 이내에 호스트 로비 목록에 해당 닉네임이 나타난다
3. **Given** 로비에 15명이 입장한 상태, **When** 16번째 참가자가 입장 시도, **Then** 정원 초과 안내가 표시되고 입장이 거부된다
4. **Given** 로비에 참가자가 있는 상태, **When** 참가자의 연결이 끊김, **Then** 호스트 로비에서 해당 참가자가 끊김 상태로 표시된다

---

### User Story 2 - 펭귄 빙판 걷기 플레이 (Priority: P1)

호스트가 게임을 시작하면 모든 폰이 컨트롤러 화면(좌/우 버튼)으로 전환되고, 호스트
화면에 참가자별 펭귄이 놓인 가로 트랙 레이스 뷰가 나타난다. 참가자는 30초 동안
좌/우 버튼을 번갈아 탭해 펭귄을 전진시킨다. 같은 쪽을 연속으로 누르거나 박자가
깨지면 펭귄이 기울고, 기울기 한계를 넘으면 꽈당 넘어지며 기록이 확정된다.

**Why this priority**: 제품의 본체. US1과 함께 있어야 최소한의 완성된 게임이 된다.

**Independent Test**: 로비에서 1명 이상으로 게임 시작 → 30초 레이스가 진행되고 폰
입력이 호스트 화면 펭귄 이동에 반영되면 통과.

**Acceptance Scenarios**:

1. **Given** 로비에 1명 이상 입장, **When** 호스트가 시작, **Then** 모든 폰이 컨트롤러 화면으로 전환되고 호스트에 카운트다운 후 레이스가 시작된다
2. **Given** 레이스 진행 중, **When** 참가자가 좌/우를 교대로 탭, **Then** 펭귄이 전진하고 기울기가 소폭 회복된다
3. **Given** 레이스 진행 중, **When** 같은 쪽 버튼을 연속으로 탭, **Then** 그 방향으로 기울기가 크게 증가한다
4. **Given** 기울기가 한계(±100)를 초과, **When** 넘어짐 발생, **Then** 폰에 넘어짐 피드백이 표시되고 호스트 화면에서 펭귄이 미끄러지는 연출과 함께 기록이 확정된다
5. **Given** 레이스 진행 중, **When** 참가자가 입력을 멈춤, **Then** 기울기가 서서히 랜덤 방향으로 흐른다
6. **Given** 레이스 진행 중, **When** 30초 경과, **Then** 모든 참가자의 기록이 확정되고 결과 화면으로 전환된다

---

### User Story 3 - 순위 발표 (Priority: P2)

레이스가 끝나면 호스트 화면에 거리 기준 1등부터 꼴등까지 순위가 발표된다. 참가자
폰에는 자신의 기록과 등수가 표시된다.

**Why this priority**: "1등부터 순위를 정하는" 요구의 마무리. US2가 있어야 의미가
있으므로 P2.

**Independent Test**: 레이스 종료 후 호스트 순위 화면과 각 폰의 개인 결과가 실제
거리 순서와 일치하면 통과.

**Acceptance Scenarios**:

1. **Given** 레이스 종료, **When** 결과 집계, **Then** 호스트 화면에 최종 거리 내림차순으로 전체 순위가 표시된다
2. **Given** 결과 화면 표시 중, **When** 참가자가 자신의 폰 확인, **Then** 자신의 거리와 등수가 표시된다
3. **Given** 두 참가자의 최종 거리가 동일, **When** 순위 집계, **Then** 그 거리에 먼저 도달한(도달 타임스탬프가 빠른) 참가자가 상위가 된다
4. **Given** 결과 화면 표시 중, **When** 호스트가 다시 하기 선택, **Then** 같은 멤버로 로비/대기 상태로 돌아가 새 레이스를 시작할 수 있다

---

### Edge Cases

- 레이스 도중 참가자 폰이 잠기거나 브라우저가 백그라운드로 가면? → 연결이 끊기면 해당 펭귄은 그 시점 거리로 기록 확정 처리
- 레이스 도중 새 참가자가 QR로 입장하면? → 입장 차단. 방이 로비 상태일 때만 입장 가능하며, 레이스/결과 중에는 "게임 진행 중" 안내를 표시한다
- 끊긴 참가자가 같은 방에 다시 접속하면? → 닉네임·자리 승계. 기기 로컬에 저장된 playerId로 식별해 기존 슬롯에 재연결하고, 레이스 중이면 이미 확정된 기록은 유지된다 (재접속은 중도 입장 차단의 예외)
- 호스트 브라우저가 새로고침/종료되면? → 방 소멸(설계상 수용). 참가자 폰에 "방이 종료됨" 안내 표시
- 닉네임이 중복되거나 비어 있으면? → 빈 값(공백만 포함)은 거부, 중복 시 자동으로 숫자 접미사 부여(예: "지니 (2)"). 최대 길이 10자
- 폰에서 두 버튼을 동시에 누르거나 비정상적으로 빠르게 연타하면? → 최소 입력 간격 이하 입력은 무시 (임계값은 plan에서 정의)

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 호스트는 브라우저에서 방을 생성할 수 있어야 하며, 방 생성 시 참가용 QR 코드와 방 코드가 화면에 표시되어야 한다
- **FR-002**: 참가자는 QR 스캔(또는 URL 직접 입력)만으로 앱 설치 없이 폰 브라우저에서 방에 참가할 수 있어야 한다
- **FR-003**: 참가자는 닉네임을 입력해 입장하며, 시스템은 빈 닉네임을 거부해야 한다
- **FR-004**: 시스템은 방당 최대 15명까지 참가를 허용하고 초과 입장을 거부해야 한다
- **FR-005**: 호스트 화면은 로비에서 참가자 목록(닉네임, 연결 상태)을 실시간 표시해야 한다
- **FR-006**: 호스트는 참가자가 1명 이상일 때 게임을 시작할 수 있어야 한다 (2026-08-21 변경 — 혼자서도 연습 주행 가능하게, 사용자 필드 피드백)
- **FR-007**: 게임 시작 시 모든 참가자 폰은 좌/우 두 버튼의 컨트롤러 화면으로 전환되어야 한다
- **FR-008**: 좌/우 교대 탭 시 펭귄이 전진하고 기울기가 소폭 회복되어야 한다
- **FR-009**: 같은 쪽 연속 탭 시 해당 방향으로 기울기가 크게 증가해야 한다
- **FR-010**: 입력 공백 시 기울기가 서서히 랜덤 방향으로 증가해야 한다
- **FR-011**: 기울기의 절댓값이 100 이상이 되는 순간 펭귄이 넘어지고 그 시점 거리로 기록이 확정되어야 한다
- **FR-012**: 레이스는 30초 제한시간이 지나면 종료되어야 한다
- **FR-013**: 게임 판정(기울기·거리·넘어짐)은 참가자 기기에서 수행하고, 호스트에는 상태만 주기적으로 전송해야 한다
- **FR-014**: 호스트 화면은 레이스 중 모든 펭귄의 위치·기울기·넘어짐을 실시간 레이스 뷰로 표시해야 한다
- **FR-015**: 레이스 종료 후 호스트 화면에 거리 기준 전체 순위를, 참가자 폰에 개인 기록과 등수를 표시해야 한다
- **FR-016**: 넘어짐 시 빙판에서 미끄러지는 시각 연출이 호스트 화면에 표시되어야 한다
- **FR-017**: 호스트는 결과 화면에서 같은 멤버로 다시 하기를 실행할 수 있어야 한다
- **FR-018**: 시스템은 백엔드 서버 없이(P2P + 정적 호스팅) 동작해야 하며 운영 비용이 0원이어야 한다
- **FR-019**: 레이스 중 연결이 끊긴 참가자는 끊김 시점 거리로 기록이 확정되어야 한다
- **FR-020**: 시스템은 방이 로비 상태일 때만 신규 입장을 허용하고, 레이스/결과 중 신규 입장 시도에는 진행 중 안내를 표시하며 차단해야 한다
- **FR-021**: 최종 거리가 같은 참가자는 그 거리에 먼저 도달한(마지막 전진 시각이 빠른) 쪽을 상위로 집계해야 한다. 완주자 간에도 같은 기준을 적용한다
- **FR-022**: 참가자 화면은 최근 2년 내 iOS Safari(기준 기기: iPhone 13)와 Android Chrome에서 동작해야 하며 세로 모드 기준으로 설계한다. 호스트 화면은 데스크톱 Chrome 기준으로 한다
- **FR-023**: 게임 화면 텍스트는 한국어 고정으로 제공한다 (i18n 구조는 범위 밖)
- **FR-024**: 호스트 화면은 BGM과 효과음(카운트다운·넘어짐·결과 발표)을 제공해야 한다
- **FR-025**: 참가자 폰은 주요 이벤트(탭 피드백·넘어짐·레이스 시작)에 진동(햅틱)과 효과음을 제공해야 한다. 진동은 Vibration API 지원 기기(Android Chrome)에서 제공하며, 미지원 기기(iOS Safari — 기준 기기 iPhone 13 포함)는 시각 플래시 + 효과음 폴백으로 대체하는 것을 요구 충족으로 인정한다. 모바일 오디오 자동재생 제약에 따라 입장 시 사용자 제스처로 오디오를 활성화하고, 활성화 실패 시 음소거 상태를 UI에 표시한다
- **FR-026**: 연결이 끊긴 참가자는 기기 로컬에 저장된 식별자(playerId)로 같은 방에 재접속 시 기존 닉네임·자리·확정 기록을 승계해야 한다

### Key Entities

- **Room(방)**: 호스트가 생성하는 게임 세션. roomId(QR로 공유), 상태(로비/레이스/결과), 참가자 목록을 가짐. 호스트 브라우저 메모리에만 존재
- **Player(참가자)**: 닉네임, 연결 상태, 현재 레이스 상태(거리·기울기·넘어짐 여부)를 가짐
- **RaceResult(기록)**: 참가자별 최종 거리, 넘어짐 여부, 확정 시각, 등수

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 처음 온 참가자가 QR 스캔부터 로비 입장까지 30초 이내에 완료한다
- **SC-002**: 참가자 15명 동시 레이스에서 폰 입력이 호스트 레이스 뷰에 0.5초 이내로 반영된다
- **SC-003**: 게임 규칙을 설명 없이 폰 화면만 보고 10초 안에 이해하고 플레이할 수 있다 (첫 라운드에서 전원이 1회 이상 전진 성공)
- **SC-004**: 호스팅·운영 비용 0원 (정적 호스팅 + 무료 시그널링만 사용)
- **SC-005**: 한 레이스(시작→결과 발표)가 1분 이내에 끝나 여러 판을 연속으로 돌릴 수 있다

## Assumptions

- 참가자들은 같은 공간에 모여 있고 큰 화면(TV/프로젝터/모니터)을 함께 본다
- 참가자 전원이 카메라로 QR을 스캔할 수 있는 스마트폰과 인터넷 연결(모바일 데이터 또는 Wi-Fi)을 가진다
- 지인끼리의 파티 플레이이므로 치팅 방지(서버 권위 판정)는 범위 밖 — 클라이언트 판정 수용
- 호스트 브라우저 종료 시 방이 소멸하는 것은 수용된 제약
- 이번 범위는 미니게임 1종(펭귄 빙판 걷기) **단판 레이스 + 다시 하기**로 확정. 여러 미니게임 순환·누적 포인트제 파티 모드는 후속 스펙
- 계정·로그인·기록 영구 저장 없음 (세션 휘발성)
